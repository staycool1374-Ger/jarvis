# v0.3.7 — PfA Concurrency Redesign (Global/Race Variables)

**Status:** Design (Target: v0.3.7)
**Pattern:** PARAMETERISE FROM ABOVE (PfA) — Kevlin Henney, 2001/2002. Invert
dependency direction: values/context flow DOWN from the top (constructor args,
template params, injected context objects) instead of being reached as globals
from below.
**Scope:** Replaces the flat VAR-01..17 checklist in `ROADMAP.md` v0.3.7 and
remediates `docs/global-race-audit.md`.
**Phase 8 readiness:** SMP-safe design — per-CPU context objects + atomics
replace the "single-core + IRQ-off is enough" invariant.

---

## 1. Problem Statement

17 shared/volatile globals are read/written across ISR ↔ task contexts with
mixed access kinds (some `__atomic_*`, some plain, some `volatile`). Today the
system is safe only because of two undocumented crutches:

1. **Single-core UP** — no two contexts truly run in parallel.
2. **IRQ-off sections** — the timer ISR runs with interrupts masked.

Both crutches collapse under Phase 8 (SMP). The fixes must therefore be
*structural* (remove the shared state, or make its synchronization explicit and
SMP-valid), not one-off "make it atomic" patches.

PfA applies in two complementary ways:

- **A. Eliminate globals by parameterising from above.** Config/test-only
  globals become fields of injected context objects passed down from
  `kernel_init`.
- **B. Per-CPU context objects for real shared state.** The SMP corollary of
  PfA: thread an explicit `CpuContext` down per CPU instead of letting every
  ISR "grep" a global. State that must remain shared uses atomics/seqlock.

---

## 2. Design Principles (binding for v0.3.7)

1. **Every cross-context variable gets exactly ONE discipline.** Never mix
   `__atomic_*` with plain access on the same variable. `volatile` alone is not
   synchronization.
2. **Globals are config or state, never both.** Config flows down (PfA-A);
   state is owned (PfA-B).
3. **The timer ISR touches per-CPU state or atomics only.** No ISR code reads
   a plain task-context global.
4. **Anything reached via `current_task()` from an ISR is published atomically**
   (or is per-CPU owned).
5. **Reader-heavy counters use atomics or seqlock**, not `volatile` RMW.
6. **Lock ordering is documented** where a lock remains (e.g. `q.lock_` vs
   `scheduler_lock_`).

---

## 3. Target Architecture

```
kernel_init()
 ├─ SchedulerConfig cfg{...}          ── passed DOWN (PfA-A)
 │    ├─ preempt_enabled_
 │    ├─ sporadic_task_count_
 │    └─ suppress_terminated_log_
 ├─ TestContext *test_ctx = nullptr   ── injected by harness only (PfA-A)
 │    ├─ test_active_
 │    ├─ deadline_monitor_pid
 │    └─ dummy_save_rsp support
 └─ per-CPU bootstrap (Phase 8)       ── PfA-B
      └─ CpuContext cpu{0}
           ├─ current_task_ptr_
           ├─ isr_nesting_depth
           ├─ last_switch_tick_
           └─ wedge_emitted_
```

- `Scheduler` becomes an instance with a `const SchedulerConfig` (or keeps the
  static surface but `init(cfg)` copies config into private statics — the
  *values* are parameterised from above; the storage stays static for
  zero-per-call overhead).
- `TestContext` is a single injected struct. `nullptr` in production ⇒ all
  test flags are compile-time-false and never exist as globals.
- `CpuContext` is per-CPU (array indexed by CPU id in Phase 8; a single
  element today). ISR code takes `&cpu` from the interrupted context, never
  reads a global.

## 4. Per-Variable Remediation (replaces VAR-01..17)

| Old VAR | Variable | Today | v0.3.7 target |
|---|---|---|---|
| VAR-04 | `s_test_active_` | global bool, task write / ISR read | `TestContext::test_active`. Harness constructs one, passes down; ISR checks `test_ctx ? test_ctx->test_active : false`. No global. |
| VAR-05 | `preempt_enabled_` | boot bool | `SchedulerConfig::preempt_enabled`; set once in `Scheduler::init(cfg)`, read-only after. |
| VAR-06 | `sporadic_task_count_` | boot uint64 | `SchedulerConfig::sporadic_task_count`. |
| VAR-07 | `suppress_terminated_log_` | config bool | `SchedulerConfig::suppress_terminated_log`. |
| VAR-15 | `g_test_deadline_monitor_pid` | test inject | `TestContext::deadline_monitor_pid`. |
| VAR-16 | `scheduler_dummy_save_rsp` | test inject | part of `TestContext`/switch-request path; not a global. |
| VAR-13 | `s_wedge_emitted_`, `s_last_switch_tick_` | CONFIG_DEBUG statics | fold into per-CPU `DebugMonitorState` (in `CpuContext`). Debug-only, per-CPU ⇒ no race. |
| VAR-14 | `s_lk0_count`, `s_last_holder` | CONFIG_DEBUG on_tick locals | fold into `DebugMonitorState`. |

### B. PfA-B — per-CPU context (4 vars)

| Old VAR | Variable | Today | v0.3.7 target |
|---|---|---|---|
| VAR-01 | `current_task_ptr_` | global pointer, task+ISR writers | `CpuContext::current`. ISR reads `cpu->current`; context-switch epilogue publishes via `__atomic_store_n(RELEASE)` (or per-CPU since only one CPU touches its own slot). Reconcile INV-1: keep RSP-ownership scan as the authority; cache is per-CPU. |
| VAR-02 | `isr_nesting_depth` | global, asm RMW + atomic reset + plain read | `CpuContext::isr_nesting_depth`. asm operates on `cpu->...` via the per-CPU GS base (x86_64) / TPIDR (aarch64) / tp (riscv64). C++ accesses use `__atomic_*`. Single access kind. |
| VAR-09 | `Timer::ticks_` | global volatile RMW | Per-CPU counter: `CpuContext::ticks`. Writer = that CPU's timer ISR; readers use `__atomic_load_n(ACQUIRE)`. Optional seqlock if cross-CPU monotonic read needed. |
| VAR-13b | `s_last_switch_tick_` | (also in A) | `CpuContext::last_switch_tick`. |

### C. Single-owner / single-discipline (5 vars)

| Old VAR | Variable | Today | v0.3.7 target |
|---|---|---|---|
| VAR-03 | `s_scan_requested_` | volatile bool, mixed atomic+plain | Owned by the deadline-monitor task only. Write+exchange all `__atomic_*`; delete the plain `= false` at scheduler.cpp:2318 (or route through the same atomic). |
| VAR-08 | `s_deferred_kill_count` + `s_deferred_kill_tasks[]` | plain RMW, ISR+test writers | Owned by scheduler under `scheduler_lock_`; `defer_kill` and `process_deferred_kills` both take the lock (deferred kills already run in the gated tail). Count becomes a local passed to the flush; array accessed under lock only. |
| VAR-10 | `Keyboard::shift_/ctrl_/alt_/caps_` | ISR write / task read, plain bools | Byte-atomic `__atomic_*` (or pack into one atomic byte with RMW under atomic ops). Reader masks the byte. |
| VAR-11 | `MessageQueue::head/tail/count` | volatile, unlocked `is_empty/is_full` readers | `count` read via `__atomic_load_n(RELAXED)` in unlocked paths; `head`/`tail` RMW remain under `lock_`. Aligned `size_t` atomics only. |
| VAR-12 | `BufferPool::next_cookie_/pool_count_` | plain RMW, no lock | `__atomic_fetch_add` for cookie; `pool_count_` RMW under a lightweight `IrqSpinLock` or `__atomic_*` (bounded pool, contention negligible). |

### D. Deferred to Phase 8 (documented, not fixed now)

- **VAR-17 `hhdm_modified_`** — task-context only, single-core safe today. Keep
  as a VMM member; re-audit under SMP. No change in v0.3.7.

## 5. Concrete API Changes

```cpp
// NEW: kernel/task/scheduler_config.hpp (PfA-A)
struct SchedulerConfig {
    bool preempt_enabled = true;
    uint64_t sporadic_task_count = 0;
    bool suppress_terminated_log = false;
    // ... future: priority ceiling, per-CPU counts
};

// NEW: kernel/test/test_context.hpp (PfA-A, test-only)
struct TestContext {
    bool test_active = false;
    uint64_t deadline_monitor_pid = 0;
    // dummy_save_rsp support
};

// NEW: kernel/arch/cpu_context.hpp (PfA-B, Phase 8 groundwork)
struct CpuContext {
    TaskControlBlock *current = nullptr;      // atomic publish
    uint64_t isr_nesting_depth = 0;           // asm + atomic
    uint64_t ticks = 0;                       // atomic / seqlock
    uint64_t last_switch_tick = 0;
    // CONFIG_DEBUG: wedge_emitted, lk0_count, last_holder
};
inline CpuContext &current_cpu();             // GS/TPIDR/tp indexed
```

Scheduler surface changes:
- `Scheduler::init(const SchedulerConfig &cfg)` — copies config; **no global
  reads of config anywhere else**.
- `Scheduler::set_test_context(TestContext *)` — production path keeps
  `nullptr`; ISR checks via accessor that resolves to `false` when null.
- `current_task()` / `isr_nesting_depth` read via `current_cpu()`.
- asm (`isr_stubs.asm`, `syscall_entry.asm`) switch to per-CPU GS-relative
  access for `isr_nesting_depth` (x86_64: `%gs:` offsets; other arches
  analogous).

## 6. Migration Steps

1. Add `SchedulerConfig`, `TestContext`, `CpuContext` headers; thread
   `current_cpu()`.
2. Move `preempt_enabled_`, `sporadic_task_count_`, `suppress_terminated_log_`
   to `SchedulerConfig` (init path only).
3. Move `s_test_active_`, `g_test_deadline_monitor_pid`, `scheduler_dummy_save_rsp`
   to `TestContext`; gate ISR reads on `test_ctx != nullptr`.
4. Fold `s_wedge_emitted_`, `s_last_switch_tick_`, `s_lk0_count`,
   `s_last_holder` into per-CPU debug state.
5. Convert `current_task_ptr_` → `CpuContext::current` with atomic publish;
   keep RSP-ownership authority (INV-1).
6. Convert `isr_nesting_depth` (asm + C++) to per-CPU; unify all C++ access to
   `__atomic_*`.
7. `Timer::ticks_` → per-CPU atomic; update all 87 `Timer::ticks()` readers via
   the accessor (no call-site churn).
8. Fix `s_scan_requested_` plain write; unify atomics.
9. Gate `s_deferred_kill_*` under `scheduler_lock_`.
10. `Keyboard` mods → byte-atomic; `MessageQueue::count` unlocked readers →
    relaxed atomic; `BufferPool` cookie/page-count → atomic.
11. Delete the 17 globals from the audit; re-run `docs/global-race-audit.md`.

**Ordering constraint:** steps 5–6 must land together (asm + C++ touch the same
field). Steps 2–3 are independent and safe first.

## 7. Test Plan

- Existing `scheduler`, `ipc`, `sporadic`, `ipc_blocking` classes must stay
  0-failure (regression gate).
- New: `test_config_injection` — verifies `SchedulerConfig`/`TestContext`
  values reach the ISR-visible path and are false/zero when `nullptr`.
- New: `test_percpu_current` — verifies `current_cpu()` resolves the running
  task correctly and atomic publish matches RSP-ownership scan.
- `selftest` CI gate unchanged.
- Phase 8 re-audit of VAR-17 and any remaining global in `global-race-audit.md`.

## 8. Risks / Caveats

- **asm churn (step 6)** is the highest-risk item: per-CPU GS-relative
  `isr_nesting_depth` touches `isr_stubs.asm` and `syscall_entry.asm` on three
  arches. Mitigate: land per-CPU plumbing (step 1) first, keep a `#if
  CONFIG_ARCH_X86_64` gate, verify with `make build` + scheduler class.
- **Semantics of `current_task_ptr_` change** must preserve INV-1 (RSP-authoritative).
  Do not make the cache authoritative; only make its publish atomic.
- **`Timer::ticks()` 87 readers** — keep the accessor `Timer::ticks()` returning
  the per-CPU atomic; no call-site changes needed.
- **Snapshot/restore** (`capture_task_fields`, `restore_task_fields`) must
  capture/restore per-CPU fields identically to today, or test isolation
  breaks. Add to `test_isolate` buffer layout.
