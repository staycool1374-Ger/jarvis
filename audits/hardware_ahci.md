## FIX QUEUE (Confirmed Defects)

- [ ] **FLAW-01 — Unsynchronized ISR/task shared state in DmaEngine**
  - **FILE/FUNCTION:** `src/kernel/driver/dma.cpp` — `DmaEngine::start_transfer`, `DmaEngine::handle_irq`, `DmaEngine::is_busy`, `DmaEngine::abort`
  - **ROOT CAUSE:** `active_`, `callback_`, `callback_ctx_` are mutated from `handle_irq()` (interrupt context) and read/written from `start_transfer()`/`abort()` (task context) with zero mutual exclusion — only implicit sequencing is assumed. This is a data race (UB under the C++ memory model) and violates ASIL-D freedom-from-interference: a task can re-arm a transfer while the ISR is mid-dispatch of the previous completion callback, corrupting transfer state.
  - **REQUIRED FIX:** Add `kernel::SpinLock lock_;` as a member of `DmaEngine` (fixed-size, zero-allocation, stack/static storage only). Because `handle_irq()` runs in IRQ context on the same core as `start_transfer()`/`abort()`, use the IRQ-safe guard variant (local `cli`/`sti` or equivalent save-flags spinlock, e.g. `IrqSpinLockGuard`), not a plain SpinLock, to avoid self-deadlock. Wrap the check-and-set of `active_` in `start_transfer()`, the read/reset in `handle_irq()`, the read in `is_busy()`, and the reset in `abort()` under this lock. Inside `handle_irq()`, copy `callback_`/`callback_ctx_` into local stack variables *while holding the lock*, release the lock, then invoke the callback outside the critical section — never call user callbacks while holding a spinlock (bounded-blocking requirement). No heap allocation permitted.

- [ ] **FLAW-02 — Unsynchronized buffer-index swap in PingPongDma**
  - **FILE/FUNCTION:** `src/kernel/driver/dma.cpp` — `PingPongDma::start_next`, `PingPongDma::on_completion`, `PingPongDma::prepare_buf`, `PingPongDma::xfer_buf`
  - **ROOT CAUSE:** `prepare_idx_`, `xfer_idx_`, `active_`, `completed_`, `chain_cb_`, `chain_ctx_` are mutated in `start_next()` (task context) and in `on_completion()` (invoked via `pingpong_completion_cb`, called from `DmaEngine::handle_irq` — IRQ context) without any lock. The index swap in `start_next()` can interleave with `on_completion()`'s read of `xfer_idx_`, causing `prepare_buf()`/`xfer_buf()` to hand an in-flight DMA target to a producer — silent memory corruption, a direct data-integrity violation for ASIL-D.
  - **REQUIRED FIX:** Add `kernel::SpinLock lock_;` to `PingPongDma` (static member, zero-allocation). Acquire it (via the same IRQ-safe guard used in FLAW-01, since `on_completion` executes from ISR context) around the entire index-swap block in `start_next()` (from `tmp = prepare_idx_` through `active_ = true`, including the failure-path rollback swap) and around the entire mutation block in `on_completion()` (through capturing `chain_cb_`/`chain_ctx_`/the completed buffer pointer into locals). `prepare_buf()`/`xfer_buf()` must also acquire the lock for the duration of the index read and return the resolved pointer while still holding it (return-by-value of the pointer, not a racy read-then-return). Invoke `chain_cb_` only after releasing the lock, using the captured locals. No dynamic allocation.

- [ ] **FLAW-03 — Unsynchronized virtio-net TX/RX ring bookkeeping**
  - **FILE/FUNCTION:** `src/kernel/driver/virtio_net.cpp` — `virtio_net_send_frame`, `virtio_net_poll`, `add_rx_buf`
  - **ROOT CAUSE:** `dev.tx_avail_idx`, `dev.tx_avail->idx`, `dev.rx_avail->idx`, `dev.rx_last_seen_used` are shared mutable state updated by the TX path (`virtio_net_send_frame`) and the RX path (`virtio_net_poll`/`add_rx_buf`) using only `kernel::atomic_fence()` calls. A fence enforces memory *ordering*, not mutual exclusion — concurrent execution of TX and RX paths (different core, or RX invoked from an interrupt/softirq while TX runs in a task) can lose index updates or reuse a descriptor before the device has consumed it. This is a ring-corruption / data-integrity defect.
  - **REQUIRED FIX:** Add two fixed-size `kernel::SpinLock` members to `VirtioNetDevice`: `tx_lock_` and `rx_lock_` (separate locks to avoid unnecessarily serializing independent TX/RX datapaths; both are plain struct members, zero heap). In `virtio_net_send_frame`, hold `tx_lock_` across the descriptor-fill-through-avail-idx-increment sequence. In `virtio_net_poll` and `add_rx_buf`, hold `rx_lock_` across the used-ring-consume-through-avail-refill sequence (`add_rx_buf` must document that it is only called with `rx_lock_` already held, or take the lock reentrantly via a recursion-safe variant — prefer the "caller holds lock" contract to keep the lock non-recursive). Retain all existing `kernel::atomic_fence()` calls unchanged — they remain necessary for MMIO/DMA visibility ordering and are orthogonal to the added mutual exclusion.

- [ ] **FLAW-04 — AHCI global interrupt-enable with no ISR + unsynchronized destructor teardown**
  - **FILE/FUNCTION:** `src/kernel/driver/ahci.cpp` — `AhciDriver::init()` (the `hba_write(HBA_GHC, hba_read(HBA_GHC) | GHC_AE | GHC_IE);` statement) and `AhciDriver::~AhciDriver()`
  - **ROOT CAUSE:** `GHC_IE` is unconditionally asserted, but no ISR is registered or implemented anywhere in this translation unit; `PORT_IS`/`HBA_IS` are only acknowledged inside the polling path of `wait_cmd`. On level-triggered legacy INTx delivery, an unacknowledged asserted line can stall the interrupt controller for the shared IRQ — an ASIL-D freedom-from-interference violation. Separately, `~AhciDriver()` frees `ct_phys_`, `cl_phys_`, `data_bufs_`, and `rfis_phys_` and issues `port_write(p, PORT_CMD, 0)` with no interrupt masking and no lock, while `GHC_IE` is still globally enabled — a completion interrupt firing mid-teardown can touch already-freed structures (use-after-free).
  - **REQUIRED FIX:**
    1. Do not set `GHC_IE` in `init()` until an ISR is registered. Implement `AhciDriver::handle_irq()` that unconditionally reads `HBA_IS`, and for each asserted port reads and clears `PORT_IS` (`port_write(port, PORT_IS, is)`) — this must exist and be wired into the platform's IRQ vector table before `GHC_IE` is set, purely to prevent line-stuck stalls, independent of the completion-detection redesign in FLAW-05.
    2. Add `kernel::SpinLock port_lock_[AHCI_MAX_PORTS];` (fixed array member, zero heap) guarding per-port command submission/teardown.
    3. In `~AhciDriver()`, before touching any port state: clear `GHC_IE` in `HBA_GHC` (or at minimum clear the per-port `PORT_IE` register for every port) and acquire each port's `port_lock_[p]` via an IRQ-masking guard before calling `port_write(p, PORT_CMD, 0)` and before freeing `ct_phys_`/`cl_phys_`/`data_bufs_`/`rfis_phys_`, so no in-flight ISR invocation can race the free.

- [ ] **FLAW-05 — AhciDriver::wait_cmd unbounded-latency busy-poll (up to 5s)**
  - **FILE/FUNCTION:** `src/kernel/driver/ahci.cpp` — `AhciDriver::wait_cmd`, called from `read_sector`, `write_sector`, `init` with `timeout_us = 5000000`
  - **ROOT CAUSE:** The calling task spins on `PORT_CI`/`PORT_TFD` for up to 5,000,000 `io_wait()` iterations (~seconds) with no descheduling. This blocks the calling core for an unbounded-in-practice duration, starving all equal/lower-priority tasks — an outright WCET violation and inadmissible for ASIL-D, especially given `GHC_IE` infrastructure exists but is unused.
  - **REQUIRED FIX:**
    1. Add per-slot completion state, statically embedded (no heap): `struct AhciCmdCompletion { kernel::SpinLock lock; volatile bool done; volatile bool error; };` as `cmd_done_[AHCI_MAX_PORTS][AHCI_MAX_CMDS]`.
    2. In the `AhciDriver::handle_irq()` implementation from FLAW-04, after clearing `PORT_IS`, determine completed slots by diffing the previously-submitted mask against current `PORT_CI`/`PORT_SACT`; under the relevant slot's `cmd_done_[port][slot].lock` (IRQ-safe guard), set `.done = true` and `.error` from `PORT_IS_TFES`/`TFD_ERR`, then invoke the scheduler's IRQ-context wake primitive (e.g. `Scheduler::wake_task_from_irq(...)`) on the task blocked for that slot. Do not allocate or call blocking APIs from this ISR path.
    3. Replace the spin body of `wait_cmd` with: submit via `start_cmd`, then block the calling task on a per-slot wait primitive (pre-existing freestanding semaphore/futex in this RTOS, stack/static-resident wait node only) with `timeout_us` used strictly as the scheduler's maximum wait bound (task descheduled, not spinning). The ISR wake path from step 2 satisfies the wait.
    4. Ensure `GHC_IE` (per FLAW-04) is only enabled once `handle_irq` is registered, preserving fix ordering between FLAW-04 and FLAW-05.

- [ ] **FLAW-06 — virtio-blk busy-wait completion bypasses existing DMA callback infrastructure**
  - **FILE/FUNCTION:** `src/kernel/driver/virtio_blk.cpp` — `VirtioBlkDriver::submit_request`
  - **ROOT CAUSE:** `int timeout = 1000000; while (used_->idx == used_idx && --timeout > 0) { kernel::atomic_fence(); }` occupies the calling core for the full poll duration with no yield, ignoring the `kernel::dma::DmaEngine`/`DmaCallback` deferred-completion mechanism already implemented in `dma.cpp` for this exact purpose. Unbounded core occupancy under I/O load is an ASIL-D bottom-half/WCET violation.
  - **REQUIRED FIX:** Implement a virtio queue-interrupt handler for the block device that, on notification, walks the `used_` ring and completes matching requests via a fixed-size (`queue_size_`-length, statically sized, zero-heap) array of pending completion records (`DmaCallback` + context, indexed by descriptor slot). `submit_request` must deschedule the calling task on a per-request wait primitive from the freestanding sync library instead of spinning; the queue ISR performs the wakeup from IRQ context only (no allocation, no blocking calls in the handler). Retain `1000000` only as the blocked-wait's maximum timeout value, not a spin bound.

- [ ] **FLAW-07 — virtio-net TX busy-wait completion**
  - **FILE/FUNCTION:** `src/kernel/driver/virtio_net.cpp` — `virtio_net_send_frame`
  - **ROOT CAUSE:** `int timeout = 100000; while (dev.tx_used->idx == used_idx && --timeout > 0) { kernel::atomic_fence(); }` — identical class of defect to FLAW-06: unbounded core occupancy during transmit, no descheduling, no use of interrupt-driven completion.
  - **REQUIRED FIX:** Implement a TX-queue completion IRQ handler that reclaims completed TX descriptors and signals a per-send wait primitive; `virtio_net_send_frame` must block the calling task via the scheduler wait/wake API instead of spinning. This handler and `virtio_net_send_frame` both touch TX ring state — they must both acquire `tx_lock_` introduced in FLAW-03 for the ring-index manipulation, and the calling task must release/not hold `tx_lock_` while itself blocked/descheduled (acquire lock only for the ring-touching critical section, release before waiting).

- [ ] **FLAW-08 — serial.cpp fully unbounded polling loops (no timeout at all)**
  - **FILE/FUNCTION:** `src/kernel/arch/x86_64/serial.cpp` — `Serial::putchar`, `Serial::getchar`
  - **ROOT CAUSE:** `while ((inb(arch::COM1 + 5) & 0x20) == 0);` and `while ((inb(arch::COM1 + 5) & 0x01) == 0);` have no iteration bound whatsoever. A disconnected or faulty UART hangs the calling core permanently. Since this module provides early/panic-path debug output, an unbounded hang here can occur inside fault-handling code itself — the most severe possible WCET violation for ASIL-D fault containment.
  - **REQUIRED FIX:** Introduce `constexpr uint32_t SERIAL_TIMEOUT_ITERS = 100000;` (freestanding constexpr, zero allocation). Rewrite both waits as bounded `for` loops: `for (uint32_t i = 0; i < SERIAL_TIMEOUT_ITERS; ++i) { if (ready_bit_set) break; arch::io_wait(); }`. Change `Serial::putchar` to return `bool` (success/timeout) and `Serial::getchar` to either return a sentinel value on timeout or take an `[[nodiscard]] bool` + `char&` out-param signature. Update `Serial::puts` to check `putchar`'s return and abort the write loop early on timeout. All changes are pure control-flow/signature changes — no allocation, no new dependencies, preserving this file's minimal-dependency design.

- [ ] **FLAW-09 — rtc.cpp unbounded UIP-wait loop, with unchecked call sites**
  - **FILE/FUNCTION:** `src/kernel/arch/x86_64/rtc.cpp` — `RTC::wait_for_update`, and its call sites in `RTC::read_time_raw`
  - **ROOT CAUSE:** `while (rtc_read_register(REG_STATUS_A) & 0x80) { io_wait(); }` has no iteration cap — a stuck CMOS RTC hangs every caller of `read_time_raw`/`read_seconds`/`read_time` forever. Additionally, `read_time_raw` currently calls `wait_for_update()` twice without checking any return value, so even after bounding the loop the timeout signal would be silently discarded.
  - **REQUIRED FIX:** Change `RTC::wait_for_update()` to return `bool`. Add `constexpr uint32_t RTC_UIP_TIMEOUT_ITERS = 10000;` (freestanding, zero-alloc) and bound the loop: iterate up to `RTC_UIP_TIMEOUT_ITERS` times, `return true` as soon as bit 0x80 clears, `return false` if the loop exhausts. Update both call sites inside `read_time_raw` to check this return value and immediately `return false` (propagating failure through the existing `bool` return type of `read_time_raw`) if the UIP wait times out, leaving all out-parameters untouched so the existing zero-fallback behavior in `read_seconds()`/`read_time()` engages correctly.

- [ ] **FLAW-10 — Keyboard::init() unbounded PS/2 output-buffer drain loop**
  - **FILE/FUNCTION:** `src/kernel/arch/x86_64/keyboard.cpp` — `Keyboard::init` (the `while ((inb(STATUS_PORT) & 0x01) != 0) inb(DATA_PORT);` loop, prior to the bounded `for` drain that follows it)
  - **ROOT CAUSE:** This first drain loop has no iteration cap. A faulty PS/2 controller that continuously reports "output buffer full" hangs the boot path indefinitely. The second drain in the same function is correctly bounded (`for (int i = 0; i < 4; ++i)`); this first one is not, an inconsistency in the same function.
  - **REQUIRED FIX:** Bound this loop identically to the second drain: introduce `constexpr int KBD_DRAIN_MAX = 16;` (freestanding constexpr) and rewrite as `for (int i = 0; i < KBD_DRAIN_MAX && (inb(STATUS_PORT) & 0x01) != 0; ++i) { inb(DATA_PORT); }`. No allocation, no signature change required since `Keyboard::init()` is already `void` and boot-time-only; simply cap the loop.

- [ ] **FLAW-11 — No HAL delegation boundary for direct hardware access outside serial.cpp**
  - **FILE/FUNCTION:** `src/kernel/driver/ahci.cpp` (`hba_read/hba_write/port_read/port_write`), `src/kernel/driver/ata_pio.cpp` (all `inb/outb/inw/outw` call sites), `src/kernel/arch/x86_64/rtc.cpp` (`rtc_read_register/rtc_write_register`), `src/kernel/arch/x86_64/keyboard.cpp` (`inb/outb` call sites), `src/kernel/driver/virtio_pci.cpp` (PCI config accessors), `src/kernel/driver/dma.cpp` (`BmDmaChannel`, `pci_set_bus_master`)
  - **ROOT CAUSE:** Only `serial.cpp` includes `<kernel/arch/hal/io.hpp>`; every other driver listed calls `<kernel/arch/io.hpp>` free functions or dereferences `volatile uint32_t*` MMIO pointers directly, with no service-boundary indirection permitting delegation to a Ring-3 HAL service. This is a systemic architecture non-compliance with the mandated privilege-separation model required for ASIL-D fault containment (not a single-line defect).
  - **REQUIRED FIX:** Define a freestanding `HalIo` interface consistent with the existing `<kernel/arch/hal/io.hpp>` pattern (pure function-pointer struct or `constexpr`-dispatchable vtable — no RTTI, no exceptions, no heap allocation) exposing `inb/outb/inw/outw/inl/outl` and 32-bit MMIO read/write primitives. Migrate each listed file's direct hardware-access call sites to route through this interface (pure call-site substitution — same call signatures/semantics, replace the free-function calls and the raw `volatile uint32_t*` casts in `ahci.cpp`'s accessors with `HalIo`-mediated equivalents). Each file's `#include <kernel/arch/io.hpp>` is replaced with `#include <kernel/arch/hal/io.hpp>`. No behavioral change is permitted in this pass — this is strictly an indirection-layer introduction to be validated file-by-file.
